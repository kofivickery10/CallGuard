# Deploying the CallGuard AI landing site

The site is pure static HTML / CSS / SVG. No build step, no server-side runtime needed. Drop the files in your web root and point the domain at it.

---

## What's in this folder

The site is about 35 pages now, not the handful this document once listed. Rather
than enumerate them, here is the shape of it:

| Path | Purpose |
|---|---|
| `index.html` | Homepage |
| `pricing.html` | Plans (the URL stays `/pricing`; the page never shows a price) |
| `about.html`, `privacy.html`, `terms.html`, `dpa.html`, `sub-processors.html` | Company and legal |
| `application-reconciliation.html`, `scoring-calibration.html` | Capability pages |
| `use-cases/`, `compare/`, `integrations/`, `templates/` | The SEO clusters |
| `blog/` | **Generated.** Never hand-edit — see below |
| `style.css`, `home.css`, `blog.css`, `script.js`, `home.js`, `analytics.js` | Shared assets |
| `brand/`, `fonts/`, `og/`, icons | Logos, self-hosted fonts, social images |
| `robots.txt`, `sitemap.xml` | Crawler rules and the sitemap (33 URLs, regenerated by the blog build) |
| `404.html` | Not-found page |
| `.htaccess` | Apache config: HTTPS redirect, pretty URLs, security headers, GZIP, caching, legacy redirects, and the blocks described below |

**Two things in `.htaccess` matter on every deploy:**

- **Blog sources are denied.** `landing/blog/_posts/*.md` and `/blog/_template` used to be
  live, downloadable URLs. Sources now live in `content/blog/posts/`, outside the web root,
  and `.htaccess` denies the old paths. **A deploy adds and overwrites files; it never
  deletes them**, so those old files may still be sitting on the server.
- **Held briefings are noindexed.** Three regulation posts were found to cite rules wrongly.
  The corrected versions are held, so the old, wrong copies remain on the server and are
  marked `noindex, nofollow` by path. Delete that block when they are replaced, and check
  they are back in the sitemap.

## Publishing a blog post

Posts are generated. **Never hand-edit anything in `landing/blog/`** — the next build
overwrites it, and CI fails if the generated files are stale.

1. Write `content/blog/posts/<slug>.md` (in the repo root's `content/`, **not** in
   `landing/`). The slug is the filename, so `my-post.md` becomes `/blog/my-post`. Copy the
   front-matter from an existing post.
2. Run `npm run blog:build` from the repo root.
3. Upload what it wrote: `blog/<slug>.html`, `blog/index.html`, `blog/feed.xml` and
   `sitemap.xml`.

The build regenerates the index cards, the RSS feed and the sitemap's blog entries, so none
of those is ever edited by hand. It also counts the words and reading time, which is why
neither may appear in front-matter.

**Held posts.** `draft: true` keeps a post written but unpublished: it gets no page, is left
out of the index, feed and sitemap, and other posts' links to it are dropped. Removing the
flag publishes it on the next build.

The build refuses, rather than producing something wrong:

- a missing front-matter field, or a `readingTime`/`wordCount` that should be counted;
- a `related` slug that does not exist, or a post with no inbound links from published posts;
- a `useCaseLink` the body does not actually link to;
- a published post that links to a held one. **The three held regulation posts link to each
  other, so they must publish together.**
- markdown beyond the supported subset: `##` and `###` headings, paragraphs, `**bold**`,
  `[links](/path)`, and both kinds of list.

**CI checks this.** The pipeline runs `npm run blog:build` and fails if `landing/blog` or
`landing/sitemap.xml` differ from what the sources produce.

## Option 1 — Upload via cPanel File Manager (5 mins)

1. Log in to your hosting cPanel.
2. Open **File Manager**, navigate to **`public_html`** (or whatever your domain's web root is — for an addon domain it might be `public_html/callguardai.co.uk/`).
3. Select **everything in this folder, including the subfolders and the hidden
   `.htaccess`** — but not `DEPLOY.md`, which is documentation and does not belong on the
   server.
4. Drag-drop them into `public_html` (or click **Upload**).
5. **Important:** in cPanel File Manager, click **Settings** (top-right) and tick **"Show Hidden Files (dotfiles)"** so `.htaccess` is visible/uploadable.
6. Visit your domain. Done.

---

## Option 2 — Upload via SFTP (FileZilla, Cyberduck, Transmit)

1. Get SFTP credentials from your hosting panel (usually at the same place you'd find FTP).
2. Connect with your SFTP client.
3. Navigate to `public_html` (or your web root).
4. Drag the contents of the `landing/` folder into the remote folder.

```
# Example via the command line if you prefer
sftp youruser@yourhost.example.com
cd public_html
put -r landing/*
put landing/.htaccess
exit
```

# From your local repo root
rsync -avz --exclude='DEPLOY.md' \
  landing/ youruser@yourhost.example.com:/home/youruser/public_html/

## DNS + SSL setup

### DNS

Point your domain at the hosting server:

1. In your domain registrar (where you bought `callguardai.co.uk`):
   - Add an **A record**: `@` → your hosting server IP
   - Add an **A record**: `www` → same IP (or a CNAME to `@`)
2. If you also bought `getcallguardai.com`, set up a **301 redirect** to `callguardai.co.uk` in your registrar's redirect tool, *or* via cPanel's Redirects feature.

DNS propagation is usually 5–60 mins.

### SSL / HTTPS

Most cPanel hosts auto-provision a Let's Encrypt cert when DNS resolves. Check **AutoSSL** under SSL/TLS in cPanel — should turn green within 24 hours of DNS pointing at the server.

The `.htaccess` redirects HTTP → HTTPS once the cert is active. **Until SSL is up**, comment out the first three `RewriteRule` lines in `.htaccess`, or you'll redirect-loop.

## After deploying — sanity check

Visit:

- `https://callguardai.co.uk/` → homepage
- `https://callguardai.co.uk/pricing` → plans (pretty URL works thanks to .htaccess)
- `https://callguardai.co.uk/blog/` → briefings index
- `https://callguardai.co.uk/integrations/` → integrations hub (a folder URL; needs its index file)
- `https://callguardai.co.uk/sitemap.xml` and `/robots.txt`

Verify:

- ✅ HTTPS is active (green padlock)
- ✅ The page you changed actually shows the new copy — caching is immutable on versioned
  assets, so a stale CSS file means the version query string was not bumped
- ✅ No held post is in the sitemap, and each still returns `x-robots-tag: noindex, nofollow`
- ✅ `/blog/_posts/<any>.md` returns 403 and `/blog/_template.html` redirects — the old
  sources are still denied
- ✅ Nothing you did not intend to publish is reachable: a held post's URL should 404 unless
  an older copy is still on the server

A quick way to check the last three:

```bash
curl -sI https://callguardai.co.uk/blog/<held-slug> | grep -i x-robots-tag
curl -s -o /dev/null -w '%{http_code}\n' https://callguardai.co.uk/blog/_posts/<slug>.md
curl -s https://callguardai.co.uk/sitemap.xml | grep -c '<held-slug>'
```

## Setting up `hello@callguardai.co.uk` (5 mins)

The "Book a demo" CTAs all `mailto:` `hello@callguardai.co.uk`. Set up the inbox:

1. In cPanel, open **Email Accounts** → **Create**
2. Email: `hello@callguardai.co.uk`
3. Either set a password and check via webmail, OR
4. Delete the mailbox and instead create a **Forwarder** (under Email → Forwarders) sending `hello@callguardai.co.uk` → your real inbox (e.g., `you@yourdomain.com`)

Repeat for `privacy@callguardai.co.uk` and `procurement@callguardai.co.uk` (forwarders to the same place is fine).

## Updating the site later

1. Edit the HTML/CSS in this `landing/` folder — except `blog/`, which is generated
2. Re-upload the changed files (cPanel File Manager / SFTP / rsync)
3. Hard-refresh to bypass cache (`Cmd+Shift+R` on Mac, `Ctrl+F5` on Windows)

`.htaccess` caches HTML for an hour and CSS/JS/SVG for 30 days, immutably. **When you change
a shared asset, bump its version query string** in every page that links it
(`style.css?v=17`, `script.js?v=6`), or returning visitors keep the old file.

Remember that a deploy never deletes. If a page or post should disappear, remove it on the
server by hand, or redirect it in `.htaccess`.
